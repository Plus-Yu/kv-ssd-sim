# 第一版原型验收报告

日期：2026-11-13。环境：本机 WSL2 / Ubuntu 26.04，Python 3.13，CPU-only。

本文保留第一版原始测量。后续占位数据与时延控制优化已完成，见 [开销缩减报告](开销缩减报告.md)，其中包含重新测量的基线和两次优化结果。

## 结论

原生 vLLM Scheduler、KVCacheManager 与 MooncakeStoreConnector 已跑通；Mooncake 原生写入、磁盘副本建立、内存副本清理、异步恢复及字节校验均已验证。计算部分仅等待固定时长并填充 CPU 占位 KV，没有加载模型权重或执行 forward。

**本轮没有使用 FEMU。** 延迟干预位于原生 receiver GET 之前；底层文件写在本机文件系统。这是闭环功能原型，不是 NAND/FTL 性能评估，尚未实现混合 MLA/KDA。

## 其他验证

- 11 项单元测试通过，覆盖输入前缀/作用域、依赖、非法数据、保存 fence、损坏恢复和失败写入。
- 2 项原生集成测试通过：真实磁盘恢复门控，以及原生多请求 batching/父子 join。
- 5 请求 subagent 回放通过，见 [结果](../../outputs/subagents-v1/summary.json)。
- Mooncake 独立 65536-byte 磁盘独占回读通过，见 [结果](../../outputs/native-store-verified/summary.json)。
- Ruff 检查通过；163 个已安装包的依赖一致性检查通过；原生模块导入检查通过。
- bootstrap 脚本复用本地 wheels 的执行已通过；没有额外建立第二个空环境重复安装。
