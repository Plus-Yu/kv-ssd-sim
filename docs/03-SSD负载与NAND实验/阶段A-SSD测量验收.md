# 阶段 A · SSD 块层测量验收与指标

**通过。** 对步骤六六次成功运行逐次从原始归档重算，共核对 13,992 条提交与完成事件，组成 6,996 笔块 I/O。六次的全记录读写次数、字节、平均完成时延与先前验收一致。六次 GET 窗口内的读写次数与扇区数也都符合客体 NVMe 的独立计数器。全部样本来自 TP1 tiny、同一真实会话的前两轮、人工准备冷缓存。阶段 A 验证测量方法，K3 真实尺寸自然负载留给 C1/C2。[原始归档](../../evidence/kimi-k3-step6/trials.tar.gz) · [逐次结果](../../evidence/ssd-stage-a/summary.json)

## 测了哪段时间

- **全记录**覆盖归档中目标块设备的全部提交和完成，用于复算旧结果。核对挂载点、控制器、设备号、ftrace 表头保留数与写入数、实际解析行数、提交与完成配平。六次均无表头报告的覆盖，无未解析行、其他设备事件、未配对、同键在途歧义或错误完成。归档中实际出现的操作均为 R/W。带 M、A、S 的标志和提交线程名保存在明细。独立 flush、discard、其他操作单列；含 preflush 标志的数据写计入 W。
- **会话窗口**从第一轮客户端实际发送前的单调时钟标记开始，到第二轮结束后最后一次确认对象存在磁盘副本为止，采用左闭右开区间。ftrace 使用客体 mono 时钟，服务端相对时间加回其记录的单调时钟原点，客户端发送记录本身使用客体单调时钟。用发送、响应、冷准备、GET 和磁盘副本确认划分阶段。窗口包含人工冷准备与轮间等待，逐条事件保留阶段标签。
- **GET 核验窗口**沿用步骤六的 native GET 开始至 Store GET 完成，按完成事件、含两个端点统计，与 GET 前后采样的设备计数增量对照。全机累计的最终 diskstats 还包括格式化及挂载等早期 I/O，只用同窗口计数做独立对照。
- 磁盘副本确认之后每次仍有 **12–14 笔写入**。全记录与会话窗口分别汇总。归档缺少“整个设备后台排空”的独立标记，后续写入可按时间、线程和标志观察，单凭这些字段无法精确分摊到对象。自然回放应另记录 Store 队列排空、采集终点和设备尾部流量。

## 确定的指标

| 指标 | 单位、分母和边界 | 用途 |
|---|---|---|
| 读写次数、字节及各自占比 | 目标设备按 issue 计一次；字节为扇区数 × 512。次数占比分母为 R＋W 次数，字节占比分母为 R＋W 字节 | 区分访问频次和传输量 |
| I/O 大小分布 | 分读写按精确字节分组，保存每档次数与字节。图中 CDF 按笔数累计 | 识别小读、大写和合并后的设备请求 |
| IOPS、带宽与突发 | 从首个发送标记起按 1 s 和 100 ms 分箱，分别用提交笔数和 MiB 除以实际箱长。保留零值与最后一个不足整箱的区间 | 看会话各阶段的到达负载；比较峰值时注明箱宽与尾箱时长 |
| 在途深度、忙闲时间 | 在 issue 加一，在 complete 减一。峰值取事件上的最大值，均值为深度的时间积分除以窗口时长。忙时为 R/W 在途数大于零的区间并集 | 区分排队重叠、无提交但仍有在途和真正没有在途数据 I/O 的时间 |
| 地址连续性与热点 | 在同方向提交子序列中，前一笔结束扇区等于下一笔起始扇区就计为连续，分母为同方向相邻笔数。热点为按 1 MiB 对齐区域划分后最高的访问字节占比，跨界请求按覆盖字节拆分 | 描述设备接口 LBA 的顺序与空间聚集。热区图展示每笔起始地址 |
| 块层完成时延 | 按完成时间归窗。单笔为 complete 减 issue，单位 ms；记录均值、最近秩 P50/P95 与有效笔数。设备、操作、起始扇区和长度相同且有多笔同时在途时，标记歧义并剔除相应单笔时延 | 解释设备响应；错误完成使本阶段验收失败。缺少数据的方向保留空值 |

前三项回答盘收到什么，深度和地址回答何时重叠、落在何处。客体在途深度描述 Linux 块请求，闪存通道利用率、GC 和 NAND 写放大需要 FTL 计数。精确区分 MLA/KDA 与文件系统字节需要对象偏移映射。

全记录的次数与字节用于跨版本对账。GET 列为同窗口核对通过的设备读扇区数，每扇区 512 B。会话列只计第一轮发送至末次副本确认。
