# B2 验收 · 两轮自然回放的 SSD 块流量

2026-11-19。在同一 WEKA 两轮切片和 tiny MLA＋KDA 配置上完成两次独立启动的 FEMU 回放。流式组从首轮发送至设备观测结束共写 **91 笔、13.68 MiB，读为零**。其中末轮响应之后仍有 **23 笔、716 KiB** 的设备写入，占这段窗口写入笔数的 25.3%。末笔写在响应结束后 68.83 秒完成。

## 逐窗口核对

流式组使用客体单调时钟。笔数和扇区均按完成计，每扇区 512 字节。良好配平要求每个窗口的读写完成笔数、扇区数分别等于两端独立设备计数的差。两组各有 6 个窗口、7 个采样边界；本次各边界在途量均为零，窗口内确实发生过并行 I/O。采样和实际 HTTP 边界间也已检查块事件。

| 流式组窗口 | 时长（秒） | 读完成笔数 / 扇区 | 写完成笔数 / 扇区 | 写入字节 |
|---|---:|---:|---:|---:|
| 启动至首轮发送 | 328.135 | 2 / 16 | 15 / 216 | 110,592 |
| 首轮请求 | 21.841 | 0 / 0 | 33 / 13792 | 7,061,504 |
| 两轮之间 | 12.071 | 0 / 0 | 24 / 12008 | 6,148,096 |
| 第二轮请求 | 10.867 | 0 / 0 | 11 / 776 | 397,312 |
| 末轮响应至发送队列确认排空 | 5.409 | 0 / 0 | 3 / 368 | 188,416 |
| 发送队列确认排空至观测终点 | 168.497 | 0 / 0 | 20 / 1064 | 544,768 |

首轮发送前设备已发生读写，表中单列启动期。两轮之间保留原始 think time 和缓存；第二轮本地复用了 71,168 个 tokens，未发起 Store GET。轮间写入和末轮响应后的写入都计入设备时间线。两组均使用 TCG、2 vCPU、4 GiB 客体、384 MiB FEMU BlackBox 和 ext4；prefill/decode 模拟预算为 10/2 ms。TP1、两层缩放几何用于测量链验收。正式的 K3 真实尺寸负载结果留在 C1/C2。

## 如何判定采集完整

- 启动前清空 ftrace 缓冲，使用 mono 时钟记录 issue 与 complete。流式组持续读 trace_pipe，经 9p 写入宿主共享目录；采集目录与被测盘设备号分别为 28 和 66304。缓冲组开启相同的内核事件和边界探针，停止跟踪后一次性导出。
- 流式组解析 216 条事件，等于两个 CPU 的内核 read events 增量之和；缓冲组解析 234 条，与内核缓冲头一致。两组 per-CPU overrun、commit overrun、dropped events 均为零。issue/complete 全部配对，错误完成与歧义配对均为零。
- 发送时间取 AIPerf 原始 HTTP 计时，响应时间取服务端写完 SSE 的事件。独立读取目标 NVMe 的 stat，并记录读取前后的时刻；若读计数期间或与实际 HTTP 边界之间发生 I/O，验收器会报告歧义。另行核对每个边界的在途量，允许上个窗口提交的请求在本窗口完成。
- 发送队列排空取自原生 connector 的 sender 队列，在 drain 返回后确认 unfinished_tasks 为零。这个时点是确认队列已空的时刻。流式组在此之后仍记录到 20 笔设备写。客体回放及随附验证退出后，采集器继续观察，直到设备至少连续 5 秒在途为零且相关计数稳定，全程未为此强制刷盘。最后一个设备完成事件、观测终点分别距末轮响应 **68.83 秒**和 **173.91 秒**。两者间包含空闲和客体验证时间。
- 尾部计入同盘文件系统活动。尚缺对象到 LBA 的映射，单笔写入的 MLA、KDA 或文件系统归属仍待验证。

在流式原始记录的内存副本上做了两项故障校验。去掉末尾两条记录后，验收器报告内核事件数与解析数不符；将首轮响应采样的累计写扇区加一后，验收器报告首轮设备计数 13,793 扇区、跟踪 13,792 扇区。B1 归档也用更新后的验收器复核，输出逐字节一致。

## 采集开销对照

| 采集方式 | 两轮各自 HTTP 耗时（秒） | 首发至末响应（秒） | 会话写笔数 / 字节 | 响应后写笔数 / 字节 | 响应至末次设备完成（秒） | 采集进程 CPU 秒 |
|---|---:|---:|---:|---:|---:|---:|
| 持续导出 | 21.82 / 10.85 | 44.76 | 68 / 13,606,912 | 23 / 733,184 | 68.83 | 2.84 |
| 缓冲对照 | 21.86 / 10.08 | 44.01 | 71 / 13,627,392 | 29 / 761,856 | 68.60 | 2.03 |

配对核对了 trace、线上 prompt 摘要、token 账本、输入和运行时代码哈希、设备几何及计算参数。本对会话时长差为 +0.74 秒（以缓冲组为分母 +1.7%）。CPU 秒为采集器启用后的累计进程 CPU 时间，含收尾导出；内核跟踪、应用内边界探针、9p 宿主端的成本没有单独计时。每种模式各一次，TCG、文件系统后台写回和宿主调度均可能影响时序。两次启动均以客体内新建的 ext4 为初态，FEMU 日志记录了 memlock 限制。此差值只描述本对观测，独立重复后才能估计稳定开销。

在项目根目录执行以下命令，解包目录使用新名字，保留已测原件。

```bash
(cd evidence/ssd-b2 && sha256sum -c SHA256SUMS)
audit_dir=$(mktemp -d)
tar -xzf evidence/ssd-b2/trials.tar.gz -C "$audit_dir"
.venv-aiperf/bin/python scripts/analyze_b2.py "$audit_dir/femu-b2-stream01" \
  "$audit_dir/femu-b2-buffer01" --output "$audit_dir/results"
cmp "$audit_dir/results/summary.json" evidence/ssd-b2/summary.json
```

重跑设备实验使用新的 trial 名。下列命令按顺序各启动一次空盘客体。

```bash
for mode in stream buffer; do
  .venv/bin/python scripts/run_femu.py --trial "femu-b2-${mode}-repeat01" \
    --workload aiperf --natural-cache --block-capture "$mode" \
    --input datasets/kimi-k3-b300-step1/slice.json \
    --num-blocks 4096 --max-model-len 81920 --nand-read-ns 40000 || break
done
```
