# 原型开销缩减

本次优化保留原生 vLLM 调度、KV 分配、Mooncake 对象与异步传输，以及完整的读回 SHA256 校验。没有修改模型配置、请求长度、计算预算、磁盘恢复 token 数，也没有接入 FEMU。

## 改动

1. **前缀只哈希一次。** 回放时钟开始前，按每条请求的输入和固定合成输出生成紧凑的 token/layer 摘要。每项为 32 字节，运行时无需重复扫描长前缀。
2. **批量复制调度范围。** 用现有 CPU tensor 的 NumPy 字节视图，按块复制本轮新增位置，广播展开摘要；不逐 token 构造临时 tensor。已恢复前缀和未分配位置保持原样，重复计算也从相同预生成数据恢复。
3. **用绝对截止时间控制计算阶段。** 数据复制放在计算预算内，完成后等待剩余时间；截止时间到达且复制完成后才释放原生 sender 的 HostFence。超预算时如实记录，不提前宣布完成。
4. **减少观测造成的复制和写入。** Store 全量 SHA256 改用原缓冲区视图，去掉中间 bytes 复制；事件日志每 64 条 flush，保留全量事件和线程间顺序。

预生成只写入私有摘要数组，不提前填充原生 KV pool，也不提前 PUT、建立缓存命中或宣告请求完成。它利用 trace 已知输入和固定输出 token 的实验假设；未来若引入动态生成 token，需要改成增量准备。

## 前后测量

输入相同：WEKA trace_0001 的前两条请求，输入 71175 / 72762 tokens，输出 169 / 296 tokens；第二条从磁盘恢复 71168 tokens。prefill/decode 预算仍为 10 / 2 ms。

本次重新跑了一次优化前基线、两次优化后回放。表中阶段时间由同一套 `compute_begin → compute_end` 事件计算，包含占位复制，并非只比较重新安排后的 `compute_timer_done` 之后的时间。

|---|---:|---:|
| 固定累计预算 | 5906 ms | 720 ms |
| 优化前计算阶段 | 14156.22 ms | 5895.21 ms |
| 优化后第一次 | 6115.11 ms | 777.31 ms |

准备工作并没有消失：两次回放前准备分别花费约 **253 / 244 ms**，使用 **9,241,728 字节（约 8.81 MiB）** 摘要内存。准备成本写入 `summary.json.payload_preparation`；它不计入回放阶段，但应计入工具整体启动成本。全量摘要有 512 MiB 上限，超过时明确报错，避免隐式占用无界内存。

这些是本机功能与性能回归记录，没有置信区间。第一次优化测量期间另有小型集成测试运行；第二次长请求测量单独启动，结果同样显示明显下降。仍有线程唤醒、Python 和真实存储代码的开销，当前实现不保证硬实时，也不能据此预测 GPU 性能或微秒级 NAND 差异。

## 正确性证据

- 前后 **1136 个原生 Store 对象的键和 SHA256 完全相同**，两次优化运行均通过核对。
- 磁盘独占副本、恢复校验和及“GET 完成 → 调度恢复 → 计算”事件链通过。
- 同一输入下，输出长度、外部恢复 tokens、计算 step 数和预算均相同。
- 新增测试验证原算法字节兼容、跨块复制、decode、重复计算、不覆盖恢复前缀、内存上限、提前唤醒重检、超预算不追加等待，以及缓冲日志的完整性和线程顺序。
- 原生集成测试检查预生成先于请求入队、计算不早于预算完成、sender 不早于第一步完成，以及多 agent join 与 batching。
- 最终完整测试 **19 项通过**（17 项单元测试、2 项原生集成测试）；Ruff 与依赖一致性检查通过。
- 优化后的 [0/25/100 ms 闭环对照](../outputs/overhead-closed-loop/comparison.csv) 再次通过：第二请求 TTFT 约为 42.59 / 69.68 / 137.63 ms，计算预算均为 16 ms，磁盘独占恢复和校验均通过。
