# 额度恢复后续接

脚本：`scripts/resume_after_quota.py`。使用本机已核对的 `codex exec resume SESSION_ID -`，通过标准输入提交继续指令，工作目录固定在本项目。

```bash
.venv/bin/python scripts/resume_after_quota.py \
  --session-id '实际会话 UUID' \
  --rollout '/实际路径/rollout-....jsonl' --dry-run

# 核对 dry-run 输出后，用同样参数去掉 --dry-run，并用 nohup 保持运行：
nohup .venv/bin/python scripts/resume_after_quota.py \
  --session-id '实际会话 UUID' \
  --rollout '/实际路径/rollout-....jsonl' \
  > outputs/quota-watcher.log 2>&1 &
```

如果终端找不到 `codex`，显式传 `--codex /绝对路径/codex`。本机 VS Code 扩展附带的 CLI 路径可用 `command -v codex` 查询。

触发条件是该会话 rollout 中的 `event_msg/token_count`：`rate_limits.primary.window_minutes == 300`、`used_percent >= 100` 且存在 `resets_at`。脚本等到服务端给出的重置时间再加 60 秒，只续接一次。如果周额度也耗尽，则等更晚的重置时间；缺少可靠时间时不发送。不是从当前时间盲等五小时。旧的、已经过期的耗尽记录不会触发。

明确的会话 UUID 必须与文件的 `session_meta.id` 一致；不使用 `--last`。锁文件避免同一监视器重复运行，回执防止重复发送。`outputs/quota-resume/` 保存发送状态和 CLI 输出。默认监视最多 168 小时。停止方式是终止自己启动的监视器进程。脚本不修改认证信息、不绕过额度或审批、不重试普通错误、不对其他会话发指令。

本轮已找到并核对当前会话的本地 rollout，记录中确有 300 分钟窗口的官方额度事件；监视器已在本轮任务中启动；任务完成后写入停止标记撤销，状态在 `outputs/quota-resume/watcher.json`。它只服务本轮任务，未触发实际续接发送。使用 `--stop-file` 指定完成标记；任务完成后创建标记，监视器退出，不再发送。后台运行仍要求宿主保持运行。脚本不对任意 CLI 文本错误猜测重置时间。

参考：[Codex 非交互模式官方文档](https://developers.openai.com/codex/noninteractive)。实现同时以本机 `codex exec resume --help` 为准。

重新启用时请明确新的任务范围和停止标记，勿直接删除旧任务的完成标记后让其长期等待。
