# 研究文档导航

本项目研究 agent 会话中的推理 KV 缓存如何变成单盘块 I/O，以及这些请求在 FEMU 中引起多少 NAND 编程、搬迁和擦除。目录 01–05 对应研究推进顺序。原报告中的“步骤 1–6”属于 K3 参考部署验证，“阶段 A–E”属于后续 SSD 负载实验。

**理解当前系统**可以先看三条存储路径的架构图，再沿一次旧前缀回读区分对象、文件、块和 NAND 四层指标。[对象回放器、FEMU 与真实服务器的差距](05-对象回放与外推/对象回放器-FEMU-真实服务器差距说明.md)

## 05　对象回放与外推

本阶段研究一台八卡服务器运行 Kimi K3 TP8 时，agent 会话向整机缓存卷提交哪些对象、多少字节、何时读写。当前主配置为每 rank **2,781 个 KV 块**、8 × 128 GB Store、**一块 30.72 TB 逻辑 SSD 和 24 TB KV 配额**。盘读、主机暂存、向目标 rank 的传输和请求恢复分别计时。原生文件实验核对逐键读写，FEMU 测量给定单盘的块 I/O、NAND 编程与 GC。[大容量单盘与两阶段 KV 恢复验收](05-对象回放与外推/大容量单盘与两阶段KV恢复验收.md) · [前版容量与速率实验](05-对象回放与外推/八盘逻辑卷对象回放与验收.md)

136 请求窗口的对象读为零。35 秒小容量返回用例出现自然回读，8× 与 4× 相差两个键。下一项校准是用独立会话的原生文件读逐键检验预测，并用更长的缓存前史覆盖自然替换。[八卡对象回放评审核对与验收标准](05-对象回放与外推/八卡对象回放评审核对与验收标准.md) · [单机八卡 SSD 负载研究目标与验收计划](05-对象回放与外推/单机八卡SSD负载研究目标与验收计划.md)

1. 理解输入、调度、分片、驻留层级以及逐键验收方法。[对象级回放实施与验收](05-对象回放与外推/对象级回放实施与验收.md)
2. 追踪同版本 Mooncake 如何根据分配占用、租约和落盘回执选择淘汰键。[Mooncake 原生淘汰](05-对象回放与外推/对象回放器-Mooncake原生淘汰.md)
3. 对照三套系统的参数与观测边界，区分宿主文件实跑、FEMU 的块读和物理盘的 NAND 行为。[系统差距说明](05-对象回放与外推/对象回放器-FEMU-真实服务器差距说明.md) · [三套系统架构图](05-对象回放与外推/figures/三套系统的存储路径.svg) · [旧前缀回读路径图](05-对象回放与外推/figures/旧前缀回读路径.svg)
4. WEKA kvlab 的 40 天原始 trace 提供多会话的共同时间轴。[数据集版本与选择依据](05-对象回放与外推/kvlab-40天回放数据集.md)
5. 查阅全库覆盖、n15 三次独立留出对账、参考容量的并发写入曲线和复现命令。[kvlab 首轮窗口与 SSD 对象负载验收](05-对象回放与外推/kvlab首轮窗口与SSD对象负载验收.md)
6. 核对八卡公开容量、自然回读规则和虚拟时钟的取值，以及 131,072 和 1,048,576 两种上下文的前史覆盖。[单机八卡公开参考配置与上下文覆盖](05-对象回放与外推/单机八卡公开参考配置与上下文覆盖.md)
7. 查看单盘服务、恢复路径和回放入口的重构顺序，以及每一步沿用的逐事件验收方法。[对象回放器重构方案与执行记录](05-对象回放与外推/对象回放器重构方案与执行记录.md)
