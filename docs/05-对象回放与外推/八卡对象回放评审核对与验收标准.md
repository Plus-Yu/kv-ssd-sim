## 四、优先级与验收标准

### P0　逐键校准自然回读

1. **固定输入和可比条件。** 先用 35 秒用例诊断。在相同客户端拓扑、块数、容量、初始盘态、租约和等待下，记录两端生效的轮询、计算及复制时间。先冻结预测，再采原生端。n15 的文件对照入口只接一个客户端，原生计算用固定毫秒数。公开参考启动清单的 `prefill_ms` 和 `decode_ms` 均为 `null`，实际使用 `step_timing`。若沿用现有入口，需显式提供原生计算预算并标注两端时钟差异。单独改变轮询相位或间隔、导入实测时刻，都属于校准。[原生对照入口](../../scripts/run_object_holdout.py) · [启动清单](../../evidence/tp8-public-20261125/base-launch.json)
2. **找第一个分歧。** 逐键沿 `PutStart` 占用空间、`PutEnd` 内存可读、查询或续租、offload 取源、写文件、磁盘副本确认、内存回收、GET、文件读完成、恢复完成追踪。一次 PUT 是否赶上后台轮询，会改变哪些对象先有磁盘副本、回收时哪些键还受保护，以及旧前缀回来时还剩哪一层。记录相对首个请求的时差。若回收只有相邻两次副本采样，用最后在场与首次消失的区间标注。[原生文件观测器](../../native/object_replay_observer.cpp) · [已有逐阶段配对能力](../../scripts/analyze_kvlab_native.py)
3. **用留出样本判定。** 在未参与调参的会话上，以成对的原生文件 `read_submit → read_complete` 和相应成功 GET 确认自然文件读。按请求、rank、键、字节及出现次数匹配，保留重复读、未归属事件和失败状态。报告真阳性 TP、误报 FP、漏报 FN 的次数和字节，精确率为 TP/(TP+FP)，召回率为 TP/(TP+FN)，分母为零记为未定义。写入也要逐键对账。独立窗口有自然文件读、事件可归属且闭合、读写误报与漏报均为零，才标记为“该窗口逐键复现”。有差异则列出键和首次分歧。[原生留出计数示例](../../evidence/kvlab-first-windows-20261124/validation/score-1/score.json)

### P0　用真实缓存前史测参考容量下的压力

1. **先按源数据定窗，再看结果。** 以 1M 做主实验、128K 做历史对照。登记输入哈希、单机路由、根请求到达、父子依赖、工具等待、源端及目标端并发。先选百请求级候选，事前标定预热和测量边界。相同会话的重叠候选只算一份有关联的证据。若另找压力正例，将定向样本与估计读写比例的样本分开。
2. **跨边界保留状态。** 在同一实例上连续执行预热和测量，记录测量起点的本地块占用、每客户端 Store 占用、已发布磁盘字节、在途保存和排队 I/O，以及后台尾段。源端有缺失用量、跨窗父请求或归属不明的前史时，记录排除量或初始状态假设。现有 `measurement_anchor` 已可记录本地及 Store 的部分状态。[测量起点实现](../../src/kv_ssd_sim/object_store.py)
3. **以观测结果划分压力。** 同窗报告内存分配量/容量、各客户端已发布与预留的盘上字节/配额、内存和磁盘淘汰次数、对象读写字节、读字节占比、请求结束后才提交的写字节。另按声明的时间范围计算活跃去重键字节和复用距离，避免把累计写量充作驻留量。记录占用何时接近水位、哪些轮次实际回收了对象。预热、测量及后台排空可分别对账，路由和前史可复现，即可报告该窗口。零读、零淘汰都是有效观测。“自然回读”附逐键恢复事件，“持续替换”附连续回收记录。

### P1　对象特征与设备配对

- **MLA 与 KDA 分别记账。** 按类型给出唯一键数、读写次数和字节、首次发布到复用或淘汰的时长、两次访问间的时间和不同对象字节数。各类读写之和须与对象账本一致。区分“落盘后曾从文件恢复”“仅在上层复用”“到淘汰仍未见复用”“窗口结束时仍驻留”。最后一类的后续用途未知。若报告上层复用，需要能把命中的前缀映射回对象键。[对象与复用记录](对象级回放实施与验收.md)
- **读写竞争和持续替换交给 FEMU 配对。** 用同一输入和可比容量，重建前序缓存、文件布局、盘填充度和到达节奏，记录实际偏差。在同一实例连续取样，先对对象与文件读写，再对块提交、完成、diskstats，最后取同窗 NAND 编程、GC 搬迁和擦除增量。字节 WAF 为 NAND 编程字节增量除以主机写字节增量，零主机写记 `null`。小盘结果标注几何和前史。若使用 56 GiB，先通过 38,400 条 line 的全盘一致快照验收。推广到目标盘的 QoS、WAF 或寿命，还需同盘型及相近盘态的测量。[设备验收记录](../04-n15迁移与容量验收/n15-KVM基线与56GiB容量验收.md) · [NAND 计数口径](../../scripts/analyze_nand.py)

若要把突发归因于八客户端拓扑，再在总容量、会话路由和盘态相同的条件下，对照 1 与 8 个实际客户端。分别记录各客户端的对象放置、bucket、目录到设备的映射、写入重叠和后台排空时间。[八卡拓扑验收计划](单机八卡SSD负载研究目标与验收计划.md)

### P2　有观测依据后再比较策略

只有观察到可重复的恢复瓶颈、持久化后低复用或类型间寿命差异，才针对相应现象试验恢复优先、KDA 检查点准入或按类型分桶。沿用同版本 Mooncake 基线，在相同 trace、预算、预热和初始盘态下报告收益与代价。对象层可以比较少写了哪些字节，布局对 NAND 搬迁与 WAF 的影响由配对设备窗口给出。
